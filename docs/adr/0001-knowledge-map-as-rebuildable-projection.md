# 将知识地图定义为可重建的 Wiki 投影

MyWiki 的知识地图定义为从 `wiki/` 已维护页面派生的只读导航视图，而不是第二套知识库或后台同步系统。地图只在用户显式刷新或一次明确的 ingest 流程之后重新生成；原始页面、来源、引用和页面关系仍然是唯一事实来源。第一版通过独立的本地地图查看器使用，不接入 Hermes Studio。这样可以保留 MyWiki 的 Markdown/Git/source-registry 边界，同时允许地图使用语义相似度等推断关系提供探索提示。

## Considered Options

- 后台实时同步所有 Obsidian、IMA 和 raw 内容：拒绝，越过现有来源边界并会让未经审核的内容进入导航层。
- 建立独立向量数据库作为地图主存储：拒绝，会产生第二套事实来源和迁移负担。
- 只提供一次性静态图片：拒绝，无法支持节点详情、筛选和从地图回到 Wiki 的导航。
- 直接嵌入 Hermes Studio：拒绝，会把 MyWiki 与另一个客户端的接口、发布和生命周期绑定在一起；先验证独立查看器的导航价值。

## Consequences

- 地图查看器可以独立演进和替换，不改变 MyWiki 的知识层契约。
- 第一版需要定义一个可加载的派生地图数据格式，以及从节点回到 Wiki 页面的方法。
- Hermes Studio 的播放、主题和客户端能力不自动成为 MyWiki 的需求。
